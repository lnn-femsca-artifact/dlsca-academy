## 每站必须遵守的教学契约

1. 从一个普通人能够理解的问题开始，不应在没有铺垫时一次引入多个首见缩写。
2. 先展示场景中的输入、输出和困难；从事实引出“为什么需要下一步”，再介绍专业名字。
3. 把“已知/未知/候选”固定在屏幕上；同一术语跨页面保持同一含义。
4. 至少有一份可以手算或观察真实计算的例子，而不是只写数学公式。
5. 展示关键因果链，并包含一个合理但错误的对照推理。
6. 将“观察过/点击过”与“通过理解检查”区分；允许先浏览但不应计为掌握。
7. 自由回答仅提供参考答案供反思，不声称算法已经读懂用户的解释。
8. 合成波形与教学玩具概率必须持续显著标记；不能称为真实设备实验或已训练 CNN。

## 最低要求的理解评估（应找至少 3–5 位真实零基础试学者）

每位受试者在无研究者提示下完成引导，并独立解释以下 8 个问题：
1. 为什么 AES 算法公开而密钥依然需要保密？
2. SBox 公开且可逆，为什么不知道目标 K？
3. 敏感中间值和物理泄漏模型解决的分别是什么问题？
4. 为什么同一 P 的不同候选 k 可以算出不同 V(k)？
5. 建模阶段为什么可以知道参考 K，攻击阶段为什么必须隐藏目标 K？
6. 为什么 GPIO/波形尖峰/TVLA 峰值不能直接判定最优 PoI？
7. 为什么单条 Trace 预测错误仍可能通过多迹线累积恢复密钥？
8. 为什么子密钥 Rank=0 不代表完整 AES-128 密钥恢复？

要求用户至少手算：
- 两个字节 XOR，再通过公开 SBox 确定一个中间值及其 HW；
- 两种候选在两条 Trace 上的匹配概率与联合排序；
- 两组简化采样均值/组内方差并解释相对 SNR。

评价时分别记录**正确结论**与**因果链是否成立**（不是只数关键词），每条解释让用户举出一条反例；记录卡点、跳过次数与完成时间。没有真人试学数据之前，不宣称“已证明任何小白都能学会”。

## 工程与科研验收

- AES NIST 测试向量、候选得分、PoI 统计单元测试通过。
- 学习内容完整性测试检查 12 章、17 个引导站点、36 道开放式因果练习；Browser E2E 验证故事逐步显示、反馈、计算交互与无法跳过章练习计分。
- 性能与可访问性检查：桌面/手机尺寸、键盘按钮可操作、字号与对比度，以及长文阅读和滚动体验。
- 对外保持清楚版本边界：本版本有**真实 AES 数学运算、合成 Trace 与概率教学评分**；尚未提供可复现的 PyTorch/ASCAD 全流程神经网络训练与真实硬件采集。
- 应继续优先推进 [Issue #4] 真实数据集训练实验、PoI 统一独立验证协议，以及真人新手学习效果研究。

## 版本发布规则

不能因为浏览器截图好看、组件可点或单元测试全绿，就将版本标记为“零基础教学完成”。必须提供：教学目标 → 逐步因果解释 → 可操作反馈 → 独立练习 → 测试日志 → 真实新手评估记录。
